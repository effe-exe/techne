## What to steal (principle, 1–3 bullets)
- Publish the design system like a product: dated version, 'updated N days ago', principles before components, and a light/dark switch on the docs themselves.

## Why it works
- Hero is black with white Uber Move 56/600 title, a date-stamped version '10.16.26' and 'Styleguide updated 11 days ago' — freshness is a first-class signal.
- Nav order is Get started → System principles → Design language → Components → Patterns → Extension: principles precede parts. A 'Light' theme dropdown sits next to the logo.
- Monochrome line illustrations (white strokes on black, small circle nodes) are the only decoration; cards have 3–4px radii and a single soft 0 2px 4px shadow. Mixed families: Uber Move for headings, DM Sans for UI text at 13px.

## Where it applies / where it doesn't
- Applies: any multi-product org publishing a system for internal and partner teams.
- Doesn't: tiny teams — a public styleguide site is overhead; DM Sans fallback alongside Uber Move shows the docs aren't fully on-brand.
